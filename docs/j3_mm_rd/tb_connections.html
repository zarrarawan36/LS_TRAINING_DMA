Direction is seen from the DUT: in = DUT input, your driver drives it (0 during reset); out = DUT output, your monitor samples it. All signals are synchronous to the rising edge of clk; reset is rst_n (active low, asynchronous).

3Editing tb_top, step by step

Example for the first group; repeat for every group.

// tb_uvm/sgdma_cmd_if.sv  (add it to sim/my_tb.f before your packages)
interface sgdma_cmd_if (input logic clk, input logic rst_n);
  import sgdma_pkg::*;
  sgdma_cmd_t    cmd;
  logic          valid;
  logic          ready;
  // clocking blocks for your driver(s) and monitor, optional assertions (see SPEC-00)
endinterface
// [1/3] declare your interface instance
sgdma_cmd_if cmd_if_i (.clk(clk), .rst_n(rst_n));

// [2/3] in the DUT instance replace the placeholders, e.g.
//   .cmd           (ph_cmd),   becomes
    .cmd           (cmd_if_i.cmd),
    .cmd_valid     (cmd_if_i.valid),
    .cmd_ready     (cmd_if_i.ready),
//   ... then delete the ph_* declarations of this group

// [3/3] before run_test()
uvm_config_db#(virtual sgdma_cmd_if)::set(null, "*", "cmd_vif", cmd_if_i);
// in your agent / env build_phase
virtual sgdma_cmd_if vif;
if (!uvm_config_db#(virtual sgdma_cmd_if)::get(this, "", "cmd_vif", vif))
  `uvm_fatal("CFG", "cmd_vif not found in config_db - check tb_top step [3/3]")
The cmd, data and status interfaces have the same shape in several blocks. Write them generically (signal names data/keep/last/valid/ready, cmd/valid/ready, sts/valid/ready) with clocking blocks for both sender and receiver roles.

After each step: cd sim && make run → RESULT: j3_harness_smoke_test seed=1 PASSED. A HINT: line about config_db means a name in tb_top and in your get call differ.
