J3-REPORTS

J3 sgdma_mm_rd - bug reports

Editable template: one report per design issue

Verification engineer handout
Document: J3-REPORTSRevision: 1.0Date: 13 Nov 2026IP: J3 sgdma_mm_rd

Use this page to report every design issue you find: a behaviour of the DUT that does not match the specification. A good report lets the designer reproduce the problem in minutes without asking you anything.

1Before you write a report

  1. Re-read the spec ID. Is the expected behaviour really written there? If the spec is unclear, write a question instead.
  2. Make sure your testbench is right: check the stimulus and the reference model on the waveform.
  3. Reduce: find the shortest test / seed that shows the problem; note the simulation time of the first wrong value.
  4. One report per issue. If two symptoms have one cause, write one report and mention both.
Table 1: Severity levels
SeverityMeaning
S1 criticaldata corruption or lost data, hang, wrong transfer reported as successful
S2 majora feature does not work as specified, no simple workaround
S3 minorwrong behaviour in a corner case or with a simple workaround
S4 cosmeticharmless deviation (e.g. extra idle cycle where the spec allows any timing)

Waveform screenshots go into the report (Insert waveform); keep the image files in bug_reports/diagrams/ of your deliverables folder.
