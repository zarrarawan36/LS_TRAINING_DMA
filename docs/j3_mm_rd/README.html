J3 sgdma_mm_rd - README

Getting started with the verification of sgdma_mm_rd

Verification engineer handout
Document: J3-READMERevision: 1.0Date: 13 Nov 2026IP: J3 sgdma_mm_rd

Your assignment: verify the RTL block sgdma_mm_rd (Memory read engine (AXI4 read master)) to functional coverage closure, using a UVM testbench that you build on top of the provided harness and bus agents. You receive the RTL as a design drop together with its specification; treat it like any real block delivered by a design team: the specification is the reference, the RTL may contain mistakes, and your job is to find them, report them, and prove with coverage that every feature in your test plan has been exercised.

2Getting started, step by step

  1. 0Set up and look around. Unpack your work area. Read the directory map below. Open this README in a browser (all documents work offline). Check which simulator you use: SIM=verilator (default, needs UVM_HOME), vcs, questa or xcelium.
  2. 1Run the smoke test. cd sim && make run must end with RESULT: j3_harness_smoke_test seed=1 PASSED. It proves that the RTL, the provided agents and the harness compile and run on your machine. If it fails, fix the tool setup before anything else.
  3. 2Read the specs and write test plan v1. Read SPEC-10 overview, SPEC-00 interfaces and SPEC-06 sgdma_mm_rd, plus SPEC-01 and SPEC-03 memory model. Then fill in testplan.html: every spec ID should map to a feature row. Some rows are worked examples, the others are questions to answer. Draw your UVM environment and scoreboard diagrams in draw.io and insert them in the test plan.
  4. 2bCreate your interfaces and wire tb_top. Using tb_connections.html: write one interface per port group (add the files to sim/my_tb.f), complete the three TODO markers in tb_top.sv (declare instances, replace every ph_* placeholder at the DUT, config_db::set your virtual interfaces), delete the placeholders, then rerun the smoke test: it must still pass.
  5. 3Build the environment skeleton. In tb_uvm/: env config, env with the provided agent (cfg object + config_db, see SPEC-11), empty scoreboard and coverage components connected. make run TEST=j3_base_test prints your component tree and passes.
  6. 4First directed test. Write a sequence item and a driver for your first port group and one directed sequence/test (e.g. j3_single_cmd_test). Look at the waveform (WAVES=1) and confirm the DUT does what the spec example walkthrough describes.
  7. 5Complete your own agents. Driver, monitor, sequencer, agent and config for every port group; monitors publish transactions on analysis ports; handshake / protocol checks (assertions in the interface or checks in the monitor).
  8. 6Scoreboard, reference model, random tests. Reference model computes the expected outputs from the observed inputs; the scoreboard compares every DUT output. Add random sequences and tests; list them with several seeds in sim/regress.list; run make regress.
  9. 7Analyse failures and report design issues. For every failing check decide: testbench mistake or design mistake? Re-read the spec ID. For a design issue fill in a report in bug_report.html (spec ID, test, seed, expected vs. actual, waveform time).
  10. 8Close functional coverage and sign off. Implement the covergroups of your test plan, run the regression, fill holes with new tests or constraints, justify what cannot be hit, complete coverage_report.html and the sign-off table of the test plan.

6How to run

cd sim
make run                                        # smoke test (j3_harness_smoke_test), seed 1
make run TEST=j3_base_test                     # your env builds, topology printed
make run TEST=<test> SEED=<n>                   # any test, any seed
make run TEST=<test> SEED=<n> WAVES=1           # + waves.vcd
make run TEST=<test> VERBOSITY=UVM_HIGH         # more messages
make regress                                    # every line of regress.list
make run SIM=vcs TEST=<test>                    # other simulators: vcs | questa | xcelium

Logs: sim/logs/<test>_seed<n>.log. A run passes when it has no UVM_ERROR and no UVM_FATAL (the Makefile prints RESULT: ... PASSED).

8Sign-off rule

Functional coverage only: 100 % of the covergroups / coverpoints / crosses defined in your test plan, or each hole justified in the coverage report. Code coverage is not required. In addition: every test-plan feature has a passing test (or a filed report that explains the failure), and every failure seen in the regression has been analysed.
