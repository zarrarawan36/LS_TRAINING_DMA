GLOSSARY

Glossary

AXI4, AXI4-Lite, AXI-Stream, DMA and UVM terms

Verification engineer handout
Document: GLOSSARYRevision: 1.0Date: 13 Nov 2026

Terms used across the SG-DMA documents. Spec links point to the full definition.

1Bus protocols

Table 1: Bus protocols
TermMeaning
4 KB boundaryAXI rule: an INCR burst must not cross an address that is a multiple of 4096 (0x1000). Engines split bursts there.
AXI-Stream (AXIS)Point-to-point streaming bus without addresses: TDATA, TKEEP, TLAST, TUSER, TVALID, TREADY. Data flows in packets of beats.
AXI4ARM AMBA memory-mapped bus with five independent channels: write address (AW), write data (W), write response (B), read address (AR), read data (R). Supports bursts. Used between the DMA engines and memory.
AXI4-LiteSimplified AXI4: same five channels, but every transaction is a single 32-bit beat (no bursts). Used for registers.
AxLEN / AxSIZE / AxBURSTAXI address-phase fields: number of beats - 1, bytes per beat (2 = 4 bytes), burst type.
Back-pressureThe receiver holds READY = 0 so the sender must wait. Tests must apply it to find flow-control mistakes.
BeatOne data transfer (one handshake) on a data channel: 4 bytes here.
BurstA series of beats belonging to one address phase on AXI4. Length = AxLEN + 1 beats (max 16 in this design).
Byte laneOne 8-bit slice of the 32-bit data bus. Lane 0 = bits 7:0 = lowest address (little-endian).
ChannelOne group of signals with its own valid/ready handshake (e.g. the AXI AR channel, the SG-DMA cmd channel).
FIXED burstEvery beat of the burst uses the same address. Used for FIFO-like targets (INC_SRC / INC_DST = 0).
HandshakeA transfer on a rising clock edge where VALID = 1 and READY = 1 (SPEC-00 IF-HS-001).
INCR burstIncrementing burst: beat k uses address + k × beat size. Normal memory access.
Little-endianThe byte at the lowest address is the least significant byte of a word.
OKAY / SLVERRAXI responses: 2'b00 success, 2'b10 slave error. Returned on B (writes) and on every R beat (reads).
Outstanding transactionA transaction whose address has been sent but whose response has not yet arrived. The SG-DMA masters allow one per direction.
RLAST / WLASTMarks the last beat of an AXI read / write burst.
TKEEPAXI-Stream byte qualifier: TKEEP[i] = 1 means byte lane i of TDATA is part of the stream.
TLASTAXI-Stream: marks the last beat of a packet (end of packet, EOP).
TUSER / SOPAXI-Stream sideband; in this design TUSER = 1 marks the first beat of a packet (start of packet).
VALID / READYVALID: the sender has an item. READY: the receiver can take it. The item moves only when both are 1.
WRAP burstAXI burst type that wraps at a boundary; not used in this design.
WSTRBAXI write strobes: one bit per byte lane; only lanes with WSTRB = 1 are written.

2DMA and design terms

Table 2: DMA and design terms
TermMeaning
Asynchronous resetReset that acts immediately, not waiting for a clock edge. rst_n here is active low.
ChainDescriptors linked by their NEXT_DESC pointers. Ends at NEXT_DESC = 0 or at a descriptor that is not OWNED.
CSRControl and status registers, accessed by software over AXI4-Lite.
Descriptor32-byte record in memory describing one job: source, destination, length, flags, next pointer, status (SPEC-01).
DMADirect memory access: hardware that moves data without the CPU copying it.
FIFOFirst-in first-out buffer. FWFT (first-word fall-through): the oldest entry is visible at the output without a read cycle.
Interrupt (irq)Output that tells the CPU something needs attention; here a level signal.
LevelA signal that holds its value for as long as the condition is true.
M2M / M2S / S2MMemory-to-memory, memory-to-stream, stream-to-memory transfer modes.
OWNED flagDescriptor CTRL bit 16: 1 = hardware may process it; the hardware clears it when done.
PacketA sequence of stream beats from start of packet to TLAST.
PulseA signal that is 1 for exactly one clock cycle.
Scatter-gatherThe DMA follows a list of jobs (descriptors), so data can be gathered from / scattered to many buffers.
Soft reset (SW_RESET)Reset requested by software through a register; affects only part of the state.
Sticky bitA status bit that stays set after the event until software (or reset) clears it.
W1C / RW1CWrite-1-to-clear: writing 1 to a bit clears it, writing 0 leaves it unchanged (e.g. interrupt status).
Write-backThe hardware writes the STATUS word and the updated CTRL word back into the descriptor.

3Verification terms

Table 3: Verification terms
TermMeaning
AgentUVM component grouping sequencer, driver and monitor for one interface. Active = drives, passive = only monitors.
Analysis portOne-to-many broadcast connection: monitor → scoreboard, coverage, ... (write() call).
Bug reportDocument describing one design issue: spec ID, test, seed, expected vs. actual, waveform time.
Checker / assertionCode that flags a rule violation: in the scoreboard, in a monitor, or an SVA property in an interface.
Clocking blockPart of an interface that defines when signals are sampled and driven relative to a clock; avoids races.
Code coverageMeasurement of which RTL lines / branches executed. Not part of this sign-off.
config_dbUVM configuration database: tb_top sets virtual interfaces, components get them by name.
Constrained-random testTest whose stimulus is randomised within constraints; run with many seeds.
Coverage closureReaching the coverage goal (100 % of your plan) or justifying every hole.
Coverage holeA bin that was never hit.
Covergroup / coverpoint / bin / crossCovergroup: a set of coverage items sampled together. Coverpoint: one value being measured. Bin: one value range of a coverpoint. Cross: combinations of coverpoints.
Directed testTest with hand-written specific stimulus for one feature.
DriverComponent that turns items into pin activity on the interface.
DUTDesign under test: the RTL block you verify.
FactoryUVM mechanism that creates objects by type (type_id::create) and allows overriding them.
Functional coverageMeasurement of which features / values / combinations the tests exercised, defined by you in covergroups.
Interface / virtual interfaceSystemVerilog bundle of signals; a virtual interface is a handle to it that class-based code can use.
MonitorComponent that watches pins, rebuilds transactions and publishes them on an analysis port. Never drives.
ObjectionUVM mechanism that keeps the run phase alive while a test is active.
Reactive agent / responderAn agent that answers requests from the DUT (e.g. returns a status after each command).
Reference modelModel that computes the expected outputs from the inputs, following the specification.
RegressionRunning the whole list of tests and seeds, e.g. make regress.
ScoreboardComponent that compares what the DUT did with what it should have done.
SeedNumber that initialises the random generator; same seed = same simulation.
SequenceObject that generates a series of sequence items.
Sequence item / transactionObject describing one unit of activity (one command, one beat, one register access).
SequencerComponent that passes items from sequences to the driver.
Smoke testMinimal test proving that the environment compiles and runs.
Spec IDUnique identifier of one requirement in a specification (e.g. CSR-REG-003).
SVASystemVerilog assertions: temporal properties checked by the simulator every clock.
tb_topTop-level SystemVerilog module: instantiates DUT, interfaces, clock/reset, publishes virtual interfaces, calls run_test().
Test planDocument listing features, tests, coverage and checks, mapped to spec IDs.
Testbench (TB)Everything around the DUT that drives stimulus and checks results.
UVMUniversal Verification Methodology: SystemVerilog class library for reusable testbenches.
VerbosityFilter for UVM messages: UVM_NONE, UVM_LOW, UVM_MEDIUM, UVM_HIGH, UVM_FULL, UVM_DEBUG.
Waveform / VCDRecording of signal values over time; VCD is a common file format (waves.vcd).
