1Component hierarchy

Full names show the path, e.g. uvm_test_top.env.cmd_agt.drv. Call uvm_top.print_topology() (the provided base test does) to print the tree.

2Phases

Table 1: Most used phases
PhaseKindWhat you do there
build_phasefunction, top-downcreate children with type_id::create, get config_db values
connect_phasefunction, bottom-upconnect driver ↔ sequencer, analysis ports → imps
end_of_elaboration_phasefunctionprint topology, final structural checks
run_phasetask (consumes time)drivers and monitors loop forever; the test starts sequences between raise / drop objection
extract / check_phasefunctionscoreboard: anything expected but never seen? queues empty?
report_phasefunctionprint summaries, PASS / FAIL
task run_phase(uvm_phase phase);
  phase.raise_objection(this);       // keep the simulation running
  rst_vif.wait_reset_released();
  my_seq.start(env.cmd_agt.sqr);     // do the work
  repeat (50) @(posedge rst_vif.clk); // let the last transactions drain
  phase.drop_objection(this);        // run phase ends when nobody objects
endtask

3Factory and config_db

// register every class with the factory
`uvm_component_utils(my_driver)        // components (have a parent)
`uvm_object_utils(my_item)             // objects: items, sequences, cfg

drv  = my_driver::type_id::create("drv", this);   // component: name + parent
item = my_item::type_id::create("item");          // object: name only

// tb_top (module): publish a virtual interface for everybody
uvm_config_db#(virtual toy_if)::set(null, "*", "toy_vif", toy_if_i);

// any component: get it (always check the result!)
if (!uvm_config_db#(virtual toy_if)::get(this, "", "toy_vif", vif))
  `uvm_fatal("CFG", "toy_vif not found")

// env: hand a cfg object to one agent only
uvm_config_db#(toy_cfg)::set(this, "toy_agt", "cfg", toy_cfg_h);
The name in set and get must match exactly, and the set must happen before the get (tb_top sets before run_test(); an env sets before creating the child).

4Sequence, sequencer, driver

class toy_item extends uvm_sequence_item;
  `uvm_object_utils(toy_item)
  rand bit [7:0]    payload;
  rand int unsigned gap;                       // idle cycles before this item
  constraint c_gap { gap inside {[0:5]}; }
  function new(string name = "toy_item"); super.new(name); endfunction
  virtual function string convert2string(); return $sformatf("payload=0x%02h gap=%0d", payload, gap); endfunction
endclass

class toy_rand_seq extends uvm_sequence #(toy_item);
  `uvm_object_utils(toy_rand_seq)
  rand int unsigned n = 20;
  function new(string name = "toy_rand_seq"); super.new(name); endfunction
  task body();
    repeat (n) begin
      req = toy_item::type_id::create("req");
      start_item(req);
      if (!req.randomize()) `uvm_fatal("SEQ", "randomize failed")
      finish_item(req);
    end
  endtask
endclass

5Worked example: valid/ready driver and monitor (TOY interface)

The TOY interface is made up for this example (it is not an SG-DMA port): an 8-bit payload with valid / ready, following the handshake rules of SPEC-00. The interface code is in SPEC-00, section 'Building a testbench interface'.

// ---------------- driver: SENDER side -------------------------------------
class toy_driver extends uvm_driver #(toy_item);
  `uvm_component_utils(toy_driver)
  virtual toy_chan_if vif;
  function new(string name, uvm_component parent); super.new(name, parent); endfunction

  function void build_phase(uvm_phase phase);
    super.build_phase(phase);
    if (!uvm_config_db#(virtual toy_chan_if)::get(this, "", "toy_vif", vif)) `uvm_fatal("DRV", "no vif")
  endfunction

  task run_phase(uvm_phase phase);
    vif.snd_cb.valid <= 1'b0;
    forever begin
      wait (vif.rst_n === 1'b1);
      seq_item_port.get_next_item(req);
      repeat (req.gap) @(vif.snd_cb);
      vif.snd_cb.payload <= req.payload;        // present the item ...
      vif.snd_cb.valid   <= 1'b1;
      do @(vif.snd_cb); while (vif.snd_cb.ready !== 1'b1);   // ... hold it until the handshake edge
      vif.snd_cb.valid   <= 1'b0;
      seq_item_port.item_done();
    end
  endtask
endclass

// ---------------- monitor: only samples ------------------------------------
class toy_monitor extends uvm_monitor;
  `uvm_component_utils(toy_monitor)
  virtual toy_chan_if vif;
  uvm_analysis_port #(toy_item) ap;
  function new(string name, uvm_component parent); super.new(name, parent); ap = new("ap", this); endfunction

  function void build_phase(uvm_phase phase);
    super.build_phase(phase);
    if (!uvm_config_db#(virtual toy_chan_if)::get(this, "", "toy_vif", vif)) `uvm_fatal("MON", "no vif")
  endfunction

  task run_phase(uvm_phase phase);
    forever begin
      @(vif.mon_cb);
      if (vif.rst_n !== 1'b1) continue;                     // ignore everything during reset
      if (vif.mon_cb.valid === 1'b1 && vif.mon_cb.ready === 1'b1) begin
        toy_item t = toy_item::type_id::create("t");        // a NEW object per transaction
        t.payload = vif.mon_cb.payload;
        ap.write(t);
      end
    end
  endtask
endclass
The driver of a receiver (drives only ready) does not need items at all: it can randomise ready every cycle from a percentage knob in its config object, like the provided axis slave driver.

6Reactive slave / responder pattern

When the DUT is the one that sends requests (for example a command) and the testbench must answer (for example with a status), use a reactive agent: the monitor sees the request, a sequence decides the answer, the driver drives it.

class toy_resp_sequencer extends uvm_sequencer #(toy_item);
  `uvm_component_utils(toy_resp_sequencer)
  uvm_tlm_analysis_fifo #(toy_item) req_fifo;              // monitor.ap connects here
  function new(string name, uvm_component parent); super.new(name, parent); req_fifo = new("req_fifo", this); endfunction
endclass

class toy_resp_seq extends uvm_sequence #(toy_item);
  `uvm_object_utils(toy_resp_seq)
  `uvm_declare_p_sequencer(toy_resp_sequencer)
  function new(string name = "toy_resp_seq"); super.new(name); endfunction
  task body();
    toy_item request;
    forever begin
      p_sequencer.req_fifo.get(request);                   // wait for the DUT's request
      req = toy_item::type_id::create("rsp");
      start_item(req);
      if (!req.randomize() with { payload == request.payload + 1; }) `uvm_fatal("SEQ", "randomize")
      finish_item(req);                                    // driver sends the answer
    end
  endtask
endclass
// in the agent's connect_phase:  mon.ap.connect(sqr.req_fifo.analysis_export);
// in the test:                   fork resp_seq.start(env.resp_agt.sqr); join_none

7Monitor → scoreboard

`uvm_analysis_imp_decl(_in)       // one suffix per input port of the scoreboard
`uvm_analysis_imp_decl(_out)

class toy_scoreboard extends uvm_scoreboard;
  `uvm_component_utils(toy_scoreboard)
  uvm_analysis_imp_in  #(toy_item, toy_scoreboard) in_imp;
  uvm_analysis_imp_out #(toy_item, toy_scoreboard) out_imp;
  toy_item exp_q[$];
  int n_ok, n_err;
  function new(string name, uvm_component parent);
    super.new(name, parent); in_imp = new("in_imp", this); out_imp = new("out_imp", this);
  endfunction
  function void write_in(toy_item t);                     // stimulus seen -> predict
    toy_item e = toy_item::type_id::create("e");
    e.payload = t.payload;                                // reference model: here 'output = input'
    exp_q.push_back(e);
  endfunction
  function void write_out(toy_item t);                    // DUT output seen -> compare
    toy_item e;
    if (exp_q.size() == 0) begin `uvm_error("SCB", {"unexpected output ", t.convert2string()}) return; end
    e = exp_q.pop_front();
    if (t.payload !== e.payload) begin n_err++; `uvm_error("SCB", $sformatf("exp 0x%02h got 0x%02h", e.payload, t.payload)) end
    else n_ok++;
  endfunction
  function void check_phase(uvm_phase phase);
    if (exp_q.size() != 0) `uvm_error("SCB", $sformatf("%0d expected outputs never seen", exp_q.size()))
  endfunction
  function void report_phase(uvm_phase phase);
    `uvm_info("SCB", $sformatf("compared %0d OK, %0d mismatches", n_ok, n_err), UVM_LOW)
  endfunction
endclass
// env connect_phase:  in_agt.mon.ap.connect(scb.in_imp);  out_agt.mon.ap.connect(scb.out_imp);

8Functional coverage

class toy_coverage extends uvm_subscriber #(toy_item);
  `uvm_component_utils(toy_coverage)
  toy_item t;
  covergroup cg;
    cp_payload : coverpoint t.payload { bins zero = {0}; bins low = {[1:127]}; bins high = {[128:254]}; bins max = {255}; }
    cp_gap     : coverpoint t.gap     { bins b2b = {0}; bins short_gap = {[1:2]}; bins long_gap = {[3:5]}; }
    x_pay_gap  : cross cp_payload, cp_gap;
  endgroup
  function new(string name, uvm_component parent); super.new(name, parent); cg = new(); endfunction
  function void write(toy_item t); this.t = t; cg.sample(); endfunction
  function void report_phase(uvm_phase phase);
    `uvm_info("COV", $sformatf("cg %.1f %% (payload %.1f, gap %.1f, cross %.1f)", cg.get_coverage(),
              cg.cp_payload.get_coverage(), cg.cp_gap.get_coverage(), cg.x_pay_gap.get_coverage()), UVM_LOW)
  endfunction
endclass
Sample where the information is complete and true: usually in a subscriber connected to a monitor (what really happened on the pins), not in the sequence (what you only wanted to happen).

9Messages and verbosity

Table 2: Reporting macros
MacroUseEffect
`uvm_info(ID, msg, UVM_LOW)progress and resultsprinted if verbosity ≥ level
`uvm_warning(ID, msg)suspicious but not wrongcounted, test still passes
`uvm_error(ID, msg)a check failedcounted, test FAILS, simulation continues
`uvm_fatal(ID, msg)cannot continue (missing vif, ...)simulation stops

Levels: UVM_NONE < UVM_LOW < UVM_MEDIUM (default) < UVM_HIGH < UVM_FULL < UVM_DEBUG. Run with make run TEST=... VERBOSITY=UVM_HIGH. Put per-beat messages at UVM_HIGH so normal logs stay short.

11Reading a waveform

  1. Run the failing test with the same seed and WAVES=1; open sim/waves.vcd.
  2. Find the time of the first UVM_ERROR in the log; go there in the viewer.
  3. Add the clock, reset and the valid/ready pair of the channel involved. A transfer happens only at a rising edge with both 1.
  4. Walk backwards: which input caused this output? Compare with the spec timing diagrams.
  5. Decide: did the DUT break a spec rule, or did your driver / model do something wrong?

vif not found fatalconfig_db name / type mismatch between tb_top set and component get, or get in the wrong phase

Monitor reports every item twice / wrong valuessampling on both clock edges, or re-using one object for all transactions
