SPEC-03

AXI4 Memory Model (sgdma_axi_mem)

AXI4 slave memory with backdoor, stall and error-range knobs

Verification engineer handout
Document: SPEC-03Revision: 1.0Date: 13 Nov 2026

1What this block does

sgdma_axi_mem is a simulation model of a memory with an AXI4 slave port. The DUT reads and writes it like real memory. Your testbench uses its backdoor functions to fill source buffers and descriptor chains before a test and to read destination buffers afterwards, in zero simulation time. Two knobs make the memory behave like a busy or faulty system: random stalls (ready/valid held low) and an address range that answers with SLVERR.

Used by the testbenches of sgdma_desc, sgdma_mm_rd and sgdma_mm_wr. It is already instantiated as u_mem in those tb_tops.

1.1Example walkthrough

  1. The test calls mem_vif.write_word(32'h2000, 32'h4433_2211): byte 0x11 is at 0x2000, 0x22 at 0x2001, ...
  2. The DUT issues AR: addr 0x2000, len 1 (2 beats), INCR. The memory accepts it (ARREADY = 1), waits RD_LATENCY cycles and returns two R beats: 0x4433_2211 then the word at 0x2004 (0 if never written), RLAST on the second.
  3. The DUT writes AW: 0x3000, len 0 + W: 0xAABB_CCDD, WSTRB 0011: only bytes 0x3000 (0xDD) and 0x3001 (0xCC) change. B = OKAY.
  4. The test checks with mem_vif.read_byte(32'h3001) == 8'hCC.

2Parameters and ports

Table 3-1: Parameters (tb_top uses the defaults)
ParameterDefaultDescription
RD_LATENCY2minimum cycles from the AR handshake to the first RVALID
WR_RESP_LATENCY1minimum cycles from the last W handshake to BVALID

Ports: clk, rst_n and a full AXI4 slave port s_axi_* with the signals AW (awaddr awlen awsize awburst awvalid awready), W (wdata wstrb wlast wvalid wready), B (bresp bvalid bready), AR (araddr arlen arsize arburst arvalid arready) and R (rdata rresp rlast rvalid rready), 32-bit address and data.

3Functional description

Spec IDRequirement (the design SHALL ...)
MEM-STO-001Storage is a sparse byte array covering the full 32-bit address space. A byte that was never written reads as 0x00.
MEM-STO-002Words are little-endian (IF-DAT-001): write_word(a, d) stores d[7:0] at a and d[31:24] at a+3.
MEM-WR-001AWREADY is 1 only when no write burst is in progress (one write burst at a time).
MEM-WR-002WREADY is 1 only after the AW of the current burst has been accepted. Beat k is written to AWADDR + 4*k (INCR) or to AWADDR (FIXED). Only bytes with WSTRB = 1 are written.
MEM-WR-003The burst ends after AWLEN + 1 W beats; the response comes at least WR_RESP_LATENCY cycles later. BVALID is held until BREADY = 1.
MEM-RD-001ARREADY is 1 only when no read burst is in progress. The first RVALID comes at least RD_LATENCY cycles after the AR handshake; beat k returns the word at ARADDR + 4*k (INCR) or ARADDR (FIXED); RLAST = 1 on beat ARLEN. RVALID / RDATA are held until RREADY = 1.
MEM-RD-002Read and write bursts are independent and may be active at the same time.
MEM-ERR-001Read beat whose byte address lies in the error range: RDATA = 0, RRESP = SLVERR (per beat).
MEM-ERR-002Write beat whose byte address lies in the error range: the beat is not written; BRESP = SLVERR for the whole burst. Beats outside the range are written normally.
MEM-KNB-001Stall knob set_stall_pct(p), p = 0 ... 90 (larger values are clamped to 90): in every cycle, independently, AWREADY, WREADY and ARREADY are held low with probability p %, and a gap (RVALID = 0) is inserted between R beats with probability p %.
MEM-KNB-002Memory contents and knob settings are not affected by rst_n. Reset only returns the bus state machines to idle.
The memory model does not check AXI rules (burst length, 4 KB crossing, WLAST position, stability of signals, ...). Checking what the DUT does on the bus is the job of your testbench (scoreboard, checks, assertions), using the provided passive axi4_agent.

4Backdoor API

In tb_top the interface axi_mem_bd_if mem_if_i sits next to u_mem and is published in config_db as "mem_vif". Get it in your env or test and call the functions:

Table 3-2: axi_mem_bd_if functions
FunctionDescription
write_byte(addr, data8) / read_byte(addr)one byte
write_word(addr, data32) / read_word(addr)four bytes, little-endian
clear_all()forget every byte (all read as 0 again)
set_error_range(lo, hi)beats with byte address in [lo, hi] (inclusive) get SLVERR
clear_error_range()no more SLVERR
set_stall_pct(p)random stalls, p = 0 ... 90 %
in_error_range(addr)1 if addr is inside the active error range
virtual axi_mem_bd_if mem_vif;
if (!uvm_config_db#(virtual axi_mem_bd_if)::get(this, "", "mem_vif", mem_vif))
  `uvm_fatal("CFG", "mem_vif not found")

// preload a source buffer with a known pattern
for (int i = 0; i < 64; i += 4) mem_vif.write_word(32'h2000 + i, 32'hA000_0000 + i);
mem_vif.set_stall_pct(30);                         // busy memory
mem_vif.set_error_range(32'h5000, 32'h50FF);       // faulty region
...
if (mem_vif.read_word(32'h3000) !== exp) `uvm_error("SCB", "destination mismatch")
Backdoor accesses take zero time and are invisible on the AXI bus (the monitor does not see them).
