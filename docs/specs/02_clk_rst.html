SPEC-02

Clock and Reset Generator (sgdma_clk_rst)

Testbench clock and reset generator, rst_if helper

Verification engineer handout
Document: SPEC-02Revision: 1.0Date: 13 Nov 2026

1What this block does

sgdma_clk_rst is a simulation-only model that makes the testbench clock and the active-low reset. Every testbench top instantiates it once; all DUT and testbench logic runs on its clk. A testbench can request a reset at any time through the rst_req input (the provided rst_if interface does this for you).

1.1Example walkthrough

With the default parameters (10 ns, 5 cycles): clk starts at 0 and rises at 5, 15, 25, 35, 45 ns ... rst_n is 0 from time 0 and becomes 1 right after the 5th rising edge (45 ns). Later the test calls rst_vif.apply_reset(2): rst_req goes high, rst_n drops immediately, and rst_n returns to 1 on the 5th rising edge after rst_req went low again.

3Behaviour

Spec IDRequirement (the design SHALL ...)
CLK-GEN-001clk starts at 0 at time 0 and toggles every CLK_PERIOD_NS/2.
CLK-RST-001rst_n is 0 from time 0.
CLK-RST-002rst_n is released (set to 1) synchronously to a rising edge of clk: on the RESET_CYCLES-th rising edge after time 0.
CLK-RST-003A rising rst_req sets rst_n = 0 immediately (asynchronously).
CLK-RST-004After rst_req returns to 0, rst_n is released on the RESET_CYCLES-th rising edge.

4The provided rst_if

Table 2-3: rst_if (config_db name "rst_vif")
MemberDescription
logic rst_reqconnected to sgdma_clk_rst.rst_req in tb_top
task wait_reset_released()blocks until rst_n = 1, then waits one more clock edge
task apply_reset(int unsigned cycles = 2)holds rst_req for cycles clocks, then waits until reset is released again
All DUT flip-flops use an asynchronous active-low reset. While rst_n = 0 every DUT output has its reset value (all valid outputs 0). Your drivers must drive their valid signals to 0 while rst_n = 0 (IF-RST-001), and your monitors must discard half-finished transactions when reset is asserted.
