Read this first: what the SG-DMA does, the three modes, data flow

Verification engineer handout

1What the SG-DMA does

The SG-DMA (scatter-gather direct memory access) controller moves data without help from the CPU. Software prepares a list of jobs (descriptors) in memory, writes the address of the first one into a register and sets RUN. The hardware then fetches each descriptor, moves the data it describes, writes a completion status back into the descriptor and continues with the next one. At the end it sets DONE (or ERROR) and can raise an interrupt.

Data can go from memory to memory (M2M), from memory to an AXI-Stream output (M2S) or from an AXI-Stream input to memory (S2M). The design is inspired by the scatter-gather DMA controller core described in Intel's Embedded Peripherals IP User Guide (UG-01085), re-implemented with AXI4, AXI4-Lite and AXI-Stream.

2Example walkthrough: an M2M copy of 102 bytes

  1. Software writes the descriptor of SPEC-01 Table 1-1 at 0x1000 (SRC 0x2000, DST 0x3000, LENGTH 102, flags OWNED|INC_SRC|INC_DST|GEN_SOP|GEN_EOP, NEXT 0).
  2. Software writes CSR MODE = 0 (M2M), NEXT_DESC = 0x1000, IRQ_ENABLE = 1, then CONTROL = 1 (RUN).
  3. sgdma_csr raises ctrl_run. sgdma_desc sees the rising edge, raises sts_busy and reads 8 words from 0x1000 (one 8-beat INCR burst on m0).
  4. OWNED = 1 and LENGTH ≠ 0, so sgdma_desc sends src_cmd {addr 0x2000, len 102, inc 1, id 0} to sgdma_mm_rd and dst_cmd {addr 0x3000, len 102, inc 1, id 0} to sgdma_mm_wr.
  5. sgdma_mm_rd reads 26 beats on m1 (bursts of 16 + 10 beats). The beats go through the data FIFO into sgdma_mm_wr, which writes them on m2 (16 + 10 beats; the last beat has WSTRB = 0011).
  6. Both engines return a status (bytes_done = 102). sgdma_desc writes STATUS = 0x0002_0066 to 0x1010, then CTRL with OWNED cleared to 0x1008.
  7. NEXT = 0: sgdma_desc pulses sts_done and drops sts_busy. sgdma_csr sets STATUS.DONE, clears RUN, sets IRQ_STATUS.DONE; irq rises because IRQ_ENABLE.DONE = 1.
  8. Software reads STATUS, then writes 1 to IRQ_STATUS bit 0; irq falls.

Spec IDRequirement (the design SHALL ...)
TOP-MOD-001The mode is taken from CSR MODE (cfg_mode). The CSR ignores MODE writes while BUSY = 1, so the routing never changes during a chain.
TOP-MOD-002src_cmd goes to sgdma_mm_rd in M2M/M2S and to sgdma_axis_snk in S2M; dst_cmd goes to sgdma_mm_wr in M2M/S2M and to sgdma_axis_src in M2S. Engines that are not selected never see cmd_valid = 1.
TOP-MOD-003The selected engines' status channels are routed back to src_sts / dst_sts of sgdma_desc.
TOP-AXI-001Three independent AXI4 masters: m0 = descriptor engine (read + write), m1 = read engine (read channels only), m2 = write engine (write channels only).

4Data FIFO (sgdma_data_fifo)

Synchronous first-word-fall-through FIFO between sgdma_mm_rd and sgdma_mm_wr in M2M mode.

Table 10-2: sgdma_data_fifo ports (parameter DEPTH = 32)
PortDirDescription

in_data/in_keep/in_last/in_valid, in_readyin / outwrite side (data-beat channel, SPEC-00)
out_data/out_keep/out_last/out_valid, out_readyout / inread side (data-beat channel)
Spec IDRequirement (the design SHALL ...)
TOP-FIFO-001Each entry stores one beat {last, keep, data}. in_ready = 1 while not full; out_valid = 1 while not empty; the oldest entry is visible on out_* (first-word fall-through).
TOP-FIFO-002flush (software reset) empties the FIFO in one cycle.
