How to build and run, file lists, tb_top TODO markers, config_db names

1What the harness is

The harness is everything needed to compile and run a simulation of your block on day 1: the testbench top tb_top.sv, a smoke test, the Makefile and the file lists. It runs out of the box. Your work plugs into it at clearly marked places.

2Directory layout of your work area

<ip>/                      e.g. j3_mm_rd/
  docs/                    this documentation set (open your README first)
  rtl/                     DUT RTL, sgdma_pkg, sgdma_clk_rst, sgdma_axi_mem          read-only
  dv_lib/                  provided interfaces + agents (SPEC-11)                     read-only
  harness/                 tb_top.sv (PARTIALLY WIRED - you complete it),
                           jN_harness_pkg.sv (smoke test), common include files
  tb_uvm/                  YOUR testbench: interfaces, agents, env, scoreboard, coverage
                           (pre-created files with TODO markers to fill in)
  tests/                   YOUR tests: jN_test_pkg.sv, jN_base_test, jN_first_test, ...
  sim/                     Makefile, rtl.f, dv_lib.f, harness.f      provided, do not edit
                           my_tb.f, regress.list                     yours
If a folder in your copy is named differently, the file lists in sim/*.f are the reference: they say exactly which files are compiled.

3Running simulations

Run every command from the sim/ directory.

Table 12-1: Make targets and variables
CommandWhat it does
make runbuilds if needed, runs the smoke test with seed 1
make run TEST=<name> SEED=<n>runs any test with any seed
make run TEST=<name> VERBOSITY=UVM_HIGHmore messages (UVM_LOW, UVM_MEDIUM default, UVM_HIGH, UVM_DEBUG)
make run TEST=<name> WAVES=1also writes waves.vcd (open with GTKWave or your simulator's viewer)
make run TEST=<name> PLUSARGS="+TB_TIMEOUT_NS=5000000"extra plusargs; this one raises the global watchdog (default 2 ms)
make regressruns every <test> <seed> line of regress.list, prints PASS/FAIL per line and a summary
make cleandeletes build/ and logs/
make helpprints the usage text
SIM=verilator | vcs | questa | xceliumsimulator (default verilator; set UVM_HOME for Verilator)
cd sim
make run                                    # smoke test
make run TEST=j3_first_test SEED=7          # one of your tests
make run TEST=j3_rand_test SEED=42 WAVES=1  # with waveform
make regress                                # all lines of regress.list

Each run writes logs/<test>_seed<n>.log and ends with a line RESULT: <test> seed=<n> PASSED (no UVM_ERROR, no UVM_FATAL) or FAILED. If a config_db name or test name is wrong the Makefile prints a HINT: line.

The Makefile variable TEST_PKG (default jN_test_pkg) names the package tb_top imports so that +UVM_TESTNAME can find your tests.

5tb_top: what is wired and what you add

tb_top.sv already contains: the clock/reset generator and rst_if, the provided bus interface(s) connected to the DUT, the memory model u_mem and its backdoor interface (J2-J4), the config_db::set calls for all provided interfaces, and run_test().

The DUT's simple ports are connected to placeholder signals named ph_<port> (inputs tied to 0, outputs left unused) so that everything compiles. Three numbered TODO markers show where you work:

  1. [1/3] declare your interface instances,
  2. [2/3] in the DUT instance, replace every ph_<port> by <your_if_instance>.<signal>, then delete the placeholder declarations,
  3. [3/3] publish your virtual interfaces with uvm_config_db#(virtual ...)::set(null, "*", "<name>_vif", ...) before run_test().

Rerun the smoke test after each step: it only uses the provided interfaces, so it must keep passing.

6Watchdog and waveforms

tb_top contains a global watchdog: if the simulation runs longer than +TB_TIMEOUT_NS (default 2 000 000 ns) it stops with a UVM_FATAL. This usually means a sequence or driver waits for something that never happens. WAVES=1 dumps all signals of tb_top to waves.vcd.

7Pre-created testbench files

tb_uvm/ and tests/ contain files that compile as delivered and show the intended structure (item, driver, monitor, agent per port group; env, scoreboard, reference model, coverage; base test, first test). They contain TODO markers and no checking logic: filling them in is your assignment. jN_base_test builds the env, prints the topology, waits for reset, calls body() and prints *** TEST PASSED *** or *** TEST FAILED *** in its report phase. Your tests extend it and override body().
