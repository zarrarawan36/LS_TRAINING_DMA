Verification Library (dv_lib) - Provided Interfaces and Agents

Provided interfaces, agents, items, sequences and knobs

Verification engineer handout

1What is provided

The dv_lib/ folder contains interfaces and UVM agents for the standard buses (AXI4-Lite, AXI4, AXI-Stream), the reset helper and the memory backdoor. They are finished and tested: use them, do not edit them. Each agent comes with one example sequence or usage snippet in the header of its package file.

For the simple ports of your DUT (command, status, data-beat channels and control wires) there is no agent: you write those interfaces and agents yourself, following SPEC-00 and your block spec.

2axi4lite_agent (J1)

Package axi4lite_agent_pkg. Active master: sequencer + driver + monitor (passive: monitor only).

Table 11-2: axi4lite_agent API
Class / memberDescription
axi4lite_cfgvif, is_active (UVM_ACTIVE default), trace (print every transaction)
axi4lite_itemrw (AXIL_READ / AXIL_WRITE), addr, data, strb, prot, order, aw_w_gap, resp_ready_delay; filled by driver / monitor: resp, start_time, end_time

agent.sqr / agent.apstart sequences on sqr; ap sends every completed transaction
AXIL_RESP_OKAY / AXIL_RESP_SLVERR2'b00 / 2'b10
class my_reg_seq extends axi4lite_base_seq;
  `uvm_object_utils(my_reg_seq)
  function new(string name = "my_reg_seq"); super.new(name); endfunction
  task body();
    bit [31:0] rd; bit [1:0] resp;
    write_reg(32'h1C, 32'h1234_5678, resp);                     // full write, random AW/W order
    write_reg(32'h1C, 32'hAABB_CCDD, resp, 4'b0011);            // bytes 0 and 1 only
    write_reg(32'h1C, 32'h0, resp, 4'hF, AXIL_ORDER_W_FIRST);   // data before address
    read_reg (32'h1C, rd, resp);
  endtask
endclass

5axi_mem_bd_if and rst_if

See SPEC-03 Backdoor API and SPEC-02 rst_if.

The provided monitors do not check protocol rules. They report what happened; deciding whether it was correct is the job of your scoreboard, checks and assertions.
