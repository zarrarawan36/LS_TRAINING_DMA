SPEC-06

sgdma_mm_rd - Memory Read Engine

AXI4 read engine: command to bursts to data beats to status (verified by J3)

Verification engineer handout
Document: SPEC-06Revision: 1.0Date: 13 Nov 2026

1What this block does

sgdma_mm_rd reads memory. It receives one command at a time ("read N bytes from address A"), splits the job into legal AXI4 read bursts, and sends every word it reads out on its dout_* data-beat port. When all data has left, it reports a status with the number of bytes read and an error flag.

In your testbench the AXI4 side talks to the provided memory model (monitored by the passive axi4_agent). You write the command driver, a dout receiver (which drives dout_ready) with a monitor, and a status responder/monitor.

1.1Example walkthrough

  1. Command {addr 0x0000_1000, len_bytes 10, inc_addr 1, desc_id 3} is transferred (cmd_ready was 1).
  2. 10 bytes = 3 beats: the engine issues AR addr=0x1000 len=2 size=2 burst=INCR.
  3. The memory returns 3 beats. They appear on dout: keep 1111, 1111, 0011; dout_last = 1 on the third. dout_data = RDATA of each beat.
  4. After the third beat is accepted (dout_ready), the status {desc_id 3, err 0, eop_seen 0, bytes_done 10} is presented and held until sts_ready.
  5. After the status handshake cmd_ready returns to 1.

3Functional description

3.1Commands

Spec IDRequirement (the design SHALL ...)
MRD-CMD-001cmd_ready = 1 only while idle (IF-CMD-001). Fields used: addr, len_bytes, inc_addr, desc_id; gen_sop / gen_eop are ignored.
MRD-CMD-002A command with len_bytes = 0 or addr[1:0] ≠ 0 is illegal: no AR, no dout beat; status err = 1, bytes_done = 0.

3.2Burst generation

Spec IDRequirement (the design SHALL ...)
MRD-BRS-001Every burst has ARSIZE = 2. The number of beats of the next burst is the smallest of: 16, the number of beats still needed (ceil(remaining_bytes / 4)), and - for incrementing commands only - the number of 4-byte beats left before the next 4 KB boundary.
MRD-BRS-002Incrementing command (inc_addr = 1): ARBURST = INCR; the first burst starts at addr, each following burst at the previous address + 4 × beats. No burst crosses a 4 KB boundary (IF-AXI-004).
MRD-BRS-003Fixed command (inc_addr = 0): every burst of the command has ARBURST = FIXED and ARADDR = addr; all beats read the same address.
MRD-BRS-004One burst at a time: the next AR is issued only after the RLAST beat of the previous burst (IF-AXI-005).

3.3Data output

Spec IDRequirement (the design SHALL ...)
MRD-DAT-001Every R beat produces exactly one dout beat, in order, with dout_data = RDATA.
MRD-DAT-002dout_keep = 1111 on every beat except the final beat of the command, which carries keep_mask(n) where n = 1 ... 4 is the number of bytes left: 0001, 0011, 0111 or 1111.
MRD-DAT-003dout_last = 1 on the final beat of the command only (see also MRD-ERR-001).
MRD-DAT-004The engine has a one-beat output register. RREADY is 1 only when that register is empty or is being emptied in the same cycle, so dout back-pressure stalls the AXI read data and no beat is lost.

3.4Errors and status

Spec IDRequirement (the design SHALL ...)
MRD-ERR-001If a beat arrives with RRESP ≠ OKAY: err is set; the beat is still forwarded on dout (with the data returned by the memory); the current burst is received to its end; no further burst is issued; the last beat of that burst carries dout_last = 1.
MRD-STS-001The status is presented only after the final dout beat has been accepted (dout_valid & dout_ready).
MRD-STS-002Status fields: desc_id = command's desc_id; eop_seen = 0; err as above; bytes_done = bytes delivered on dout before the first beat with an error response (equals len_bytes without error).
MRD-STS-003After the status handshake the engine returns to idle and raises cmd_ready.

4Protocol of the simple ports (for your interfaces and agents)

  • cmd (you send): suggested interface sgdma_cmd_if, name cmd_vif. Follow IF-HS-*; send the next command only when the engine is ready; cmd_valid = 0 during reset.
  • dout (the DUT sends, you drive dout_ready): suggested interface sgdma_data_if, name dout_vif. Randomise dout_ready to create back-pressure; your monitor records every handshake beat.
  • sts (the DUT sends, you drive sts_ready): suggested interface sgdma_sts_if, name sts_vif.
